## Checkout and Git rules

- This repository does not use Git worktrees. Do not create or use a separate worktree for implementation, review, testing, or subagent work.
- All modifications must happen in the same existing checkout. Subagents sharing this checkout must use disjoint file ownership and preserve unrelated changes.
- The canonical recruitment snapshot is `src/lib/jobs-scraped.json`, generated by `pnpm scrape:jobs`. Do not introduce a competing `jobs-data.json` path or replace real job records with website homepage metadata.

## Deployment (Vercel)

- Vercel project: `schneiderlins-projects/infinite-connection`, production domain `https://repo-beta-self.vercel.app`. Root dir `.`, framework Next.js, Node 24.x, region iad1. Build runs `pnpm run build` (`next build`).
- Deploy production with `pnpm dlx vercel@62.0.0 --prod --yes`. CLI versions 63+ fail with "Not authorized" on this account — always pin `vercel@62.0.0`.
- Requires a logged-in Vercel CLI (`pnpm dlx vercel@62.0.0 login`) and a linked checkout (`pnpm dlx vercel@62.0.0 link --yes --project infinite-connection --scope schneiderlins-projects`). `.vercel/` is gitignored.
- GitHub auto-deploy: enabled via `vercel git connect` (2026-10-14), so pushing to `main` also triggers a production deployment. A manual CLI deploy after pushing is harmless but unnecessary.
- Env vars live in the Vercel dashboard, never in the repo: `AUTH_SECRET` (Auth.js session encryption) and `DATABASE_URL` (Neon Postgres connection string) must be set for Production and Preview before deploying auth-related changes.

## Database

- Postgres (Neon) via Prisma 7 driver adapter `@prisma/adapter-pg`; connection string comes from `DATABASE_URL`. Schema is in `prisma/schema.prisma`; connection config (not the schema file) holds the URL in `prisma.config.ts`.
- Local development uses `prisma dev` (local Postgres over PGlite): `pnpm exec prisma dev -n default -d` starts it, then put the printed `postgres://...` URL in `.env` as `DATABASE_URL`. Stop/remove with `pnpm exec prisma dev rm default --force`.
- After changing the schema run `pnpm exec prisma migrate dev --name <change>` locally, then apply to production with `DATABASE_URL=<prod-url> pnpm exec prisma migrate deploy`.
- Auth uses Auth.js v5 (`next-auth@beta`) with a Credentials provider and JWT sessions; user records are in the `User` table.
